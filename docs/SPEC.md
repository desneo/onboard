# 产品规格

> 本文定义系统必须满足的业务能力、行为和边界，不描述具体代码结构。当前实现与使用方法见
> [`../README.md`](../README.md)，实现约束见 [`ARCHITECTURE.md`](ARCHITECTURE.md)，验收场景见
> [`TESTING.md`](TESTING.md)。

## 1. 系统定位

本系统是运行在无人机机载计算平台上的自主任务控制中心，负责：

- 连接 PX4 飞控并执行飞行动作；
- 管理本机、友机、地面站链路、任务和目标状态；
- 接收并执行地面站指令和任务；
- 编排反无人机任务；
- 与地面站及其他无人机通信；
- 上报运行状态和安全告警。

系统不实现飞控固件、地面站、摄像头驱动或中制导算法本身；中制导算法作为可信预编译库集成。

吊舱视频流中的检测和跟踪由导引头实现。机载程序完全移除 Perception 及图像相关能力，
不承担取图、图像预处理、视觉检测跟踪、图像推理或视频推流职责。

## 2. 运行环境

- 操作系统：Ubuntu 22.04；
- CPU 架构：x86_64、ARM64；
- 首要硬件平台：RK3588；
- 第一版本飞控：PX4；
- 飞控使用 UDP 且端口位于 `14580`～`14589`（`1458*`） 时判定为仿真飞机，判定结果通过 `VehicleInfo.isSim` 上报。

运行主日志默认直接写入 `logs/plane.log`，不按日期创建子目录；重启后追加。
单文件达到 50 MB 后按序号轮转，历史文件为 `plane.1.log` 至 `plane.5.log`，超过保留数量淘汰最旧文件。

## 3. 飞控与状态

### 3.1 飞控连接

- 必须支持通过 UDP 或串口连接 PX4。
- 必须监测飞控连接建立、异常和恢复，并向业务模块提供当前链路状态。
- 飞控异常不得导致业务模块直接依赖 MAVSDK 或 PX4 细节。

### 3.2 飞机状态

系统必须维护本机和通过机间通信获得的友机最新状态，包括：

- WGS84 经纬度、椭球高和相对起飞点高度；
- Roll、Pitch、Yaw；
- NED 速度和空速；
- 电压、飞行模式和飞控连接状态。

旧状态被新状态替代后不得继续作为当前状态使用。

友机上下线使用 Zenoh liveliness 存活标记感知，只在上线、下线及恢复上线时打印日志。
位置、速度等状态报文更新缓存并发布内部事件，不逐条打印；不增加基于状态报文的业务离线计时。

### 3.3 状态上报

- 必须按可配置周期向地面站和其他无人机发送本机状态。
- 必须向地面站上报当前任务状态、行为树和执行节点。
- 无任务时上报无任务；独立 Command 不产生 Task 状态。
- 必须依据最近收到地面站报文的时间维护地面站链路状态，超时阈值可配置。

## 4. Command 与 Task

### 4.1 控制模型

- 任意时刻最多执行一个 Task 或一个独立 Command。
- 不维护任务队列或指令队列。
- 新控制内容到达时，立即终止当前内容并执行最新内容。

### 4.2 基础指令

必须支持：

- Arm、Disarm、Takeoff、Land、RTL；
- Waypoint、Route、Hover；
- StopMotor。

补充规则：

- 未指定起飞高度时使用当前默认安全高度。
- NED 速度是机载内部控制能力，不允许地面站直接下发。
- 中制导可以使用 Attitude Offboard；设定值必须校验、缓存，并以 50 ms 周期重发。
- StopMotor 只能由地面站人工触发，任务和其他机载模块不得自主触发。
- 指令完成必须依据实际状态判断，不能只依据指令下发成功。
- Route 航线飞行不设置执行超时，持续等待飞控任务进度完成；新的 Task 或 Command 仍可中止并替换当前航线。
- Route 开始前必须通过当前位置的临时非穿越航点调整到首航点的相对起飞点高度；未起飞时先自动解锁并起飞到默认安全高度。

### 4.3 任务

- Task 表达任务意图，不包含 Command 序列或 BehaviorTree 结构。
- Task 只能由地面站下发，其他无人机不得向本机下发。
- 收到 Task 后必须返回接收确认；确认只表示已经收到。
- 必须支持使用匹配的任务 ID 中止当前任务。
- 任务步骤顺序执行；任一步骤失败后不得继续后续步骤。
- 任务状态包括待执行、执行中、完成、中止和失败；结束后回到无任务状态。

## 5. 反无人机任务

本版本恢复 `AntiUav` 的中制导阶段，不恢复本地视觉和末制导：

- 已在空中时直接进入 Midcourse；未在空中则按解锁状态执行 Arm／Takeoff 后进入 Midcourse；
- 指定 `targetTrackId` 时锁定该航迹；未指定时只允许自动锁定唯一候选，多个候选必须失败；
- 目标管理从进程启动起持续缓存每个航迹最近 20 帧；进入中制导后直接使用已有严格递增历史，不足时最长等待 30 秒，初始化参考点使用本机起始位置，估计周期使用时间戳间隔中位数；
- Flight Control 在连接建立后读取并缓存 `MPC_XY_VEL_MAX`、`MPC_Z_VEL_MAX_UP`、
  `MPC_Z_VEL_MAX_DN`、`MPC_ACC_HOR_MAX` 四项 PX4 飞控系统参数，断连时使缓存失效、重连后重新读取；
  中制导仅作为缓存读取方，不得在任务路径实时查询 PX4 参数；
- 中制导依次调用规划器 `setConfig` 和目标估计器 `init`；此后每个 50 ms tick 先更新规划器并下发控制，再按时间顺序用全部新雷达测量更新目标估计器，使新估计在下一 tick 生效；
- 飞控系统参数缓存未就绪或算法调用失败时任务失败并停止 Offboard；
- 第 21 帧前允许算法输出悬停；雷达中断超过 3 秒后仍保持任务运行并执行算法返回的保持指令；
- 不调用末端交接确认，不设置中制导阶段总超时；任务持续到 Task Stop、新控制内容或进程退出；
- Stop、任务替换及异常退出必须停止 Offboard、清空设定值并重置中制导会话。

## 6. 图像职责边界与目标管理

### 6.1 图像能力移除范围

- 完全移除 Perception 实现、接口、事件和 DisabledPerception 占位实现。
- 移除机载图像采集、预处理、检测跟踪、画面叠加、编码及视频推流相关内容。
- 移除对应视觉插件管理、模型及算法配置、图像配置项、构建依赖和媒体测试要求。
- 保留通用 PluginManagement 模块，当前可为空实现，用于后续非图像插件扩展。
- 启动和部署不检查或安装图像模型、RKNN、视觉插件及媒体运行库。
- 本次集成不新增视觉导引头接入或末制导控制能力。

### 6.2 相机／吊舱控制

- 保留相机控制模块，用于向吊舱发送控制指令和获取状态。
- 相机控制接口不传递图像帧，不依赖 OpenCV。
- 本次修改不新增具体吊舱 SDK 或协议实现。

### 6.3 目标管理

- 本地目标管理不再订阅 Perception 检测事件或保存本地图像检测结果。
- `GcsTarget` 包含字符串航迹 ID、雷达扫描 Unix 毫秒时间戳、WGS84／MSL 位置、径向速度和方位角。
- 同一航迹只接受时间戳严格递增的数据，每个目标保留最近 20 条历史。
- 雷达入口已提供 WGS84 坐标；本版本不做雷达坐标转换、视觉目标地理定位或轨迹平滑。

## 7. 通信

### 7.1 地面站

地面站至少能够下发指令、任务、任务中止、系统参数和目标信息，并获取：

- 本机状态；
- 当前任务状态；
- 系统告警；
- 任务接收确认。

视频流不由机载程序采集、处理或转发。

配套 GCS 雷达入口默认监听 UDP `0.0.0.0:7790`，只处理 `radar_tracks`：

- 忽略 schema 版本差异和未知字段，只发布 `state=confirmed` 的航迹；`target_truth` 不参与业务处理；
- 7790 只承载雷达扫描，不要求包含防守飞机航迹；友机坐标来自 Zenoh `VehicleState`；
- 友机状态按发送方缓存 3 秒，按 NED 速度外推到扫描时间，使用三维距离做全局一对一匹配；
- 50 米内实际匹配到的友机航迹被过滤，未匹配的 confirmed 航迹作为靶机发布；
- 友机没有出现在雷达扫描中不阻塞该帧；尚无友机状态或存在过期状态时整帧暂停转发；
- 靶机数据尽力发布，不增加 Ack 或重发。

### 7.2 机载信息与主动查询

- 新增 `MessageType::VehicleInfo`，包含 `planeId`、任务板 IP `boardIp`、吊舱视频流地址 `podVideoUrl`、是否为仿真飞机 `isSim`（bool，默认 false）。
- `isSim` 直接读取现有 AppConfig.is_sim 的判定结果，不增加独立配置项；只在 VehicleInfo 中增加，不修改 VehicleState。
- IP 和视频地址在启动时从配置加载到长期维护的 AppConfig；每次发送或查询时读取当前配置值，未配置时为空。
- 机载通信启动后上报一次；配置的地面站上线或恢复上线时再次上报，不周期发送。
- 地面站先订阅 `sendToStation`，再声明 `station/liveliness/<station_id>`；重复在线通知不重复上报。
- 支持 Zenoh 原生 get/queryable 查询 `queryToPlane/<planeId>/VehicleInfo`，返回标准 Message 信封。
- 查询接口以飞机 ID 和 MessageType 选择信息，当前只支持 VehicleInfo；非法参数、不支持的类型、无响应或错误响应必须明确返回失败。
- 信息查询为只读操作，不触发任务或飞行动作；视频地址仅作为元数据传递。

### 7.3 无人机间

- 第一版本支持最多 8 架无人机参与业务通信。
- 必须支持状态交换、指定飞机单播和面向其他节点的 `sendToAll`。
- `sendToAll` 表示投递给除本机外的节点，不要求使用网络层广播；无线通信优先单播。

### 7.4 可靠性

- 任务、指令等控制消息必须具备接收确认和可靠传输机制。
- 实时状态允许丢失，以最新有效状态为准，不逐条确认。

## 8. 系统参数与安全

- 必须维护默认安全高度，支持启动配置和地面站运行时更新。
- 实机必须在飞控连接正常时监测低电压，并向地面站发送告警。
- 第一版本低电压只告警，不自动返航、降落、中止任务或接管友机任务。
- 仿真飞机不执行低电压告警。

## 9. 非目标

第一版本不要求：

- APM 飞控；
- Body 坐标系速度控制；
- 任务优先级、暂停恢复、队列或并行执行；
- 历史任务查询；
- 雷达坐标转换、目标轨迹平滑或视觉目标地理定位；
- 盘旋半径、电子围栏和禁飞区；
- 电量百分比；
- 固定 CPU、内存、延迟或吞吐量指标。
